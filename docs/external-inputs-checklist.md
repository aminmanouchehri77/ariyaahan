# چک‌لیست ورودی‌های لازم برای اتصال و انتشار

این فهرست مواردی را مشخص می‌کند که برای تکمیل اتصال‌های واقعی یا انتشار عمومی باید از مالک کسب‌وکار و حساب‌های سرویس دریافت شوند. رمزها، کلیدها و tokenها را در Git یا گفت‌وگوی معمولی نفرستید؛ آن‌ها را از prompt اسکریپت محلی یا مدیریت اسرار محیط استقرار وارد کنید.

## تنظیم پیامک کاوه‌نگار

- فعال‌بودن وب‌سرویس پیشرفته در حساب کاوه‌نگار.
- یک الگوی Verify Lookup تأییدشده برای ورود مشتری و یک الگوی جداگانه برای پذیرش پیش‌فاکتور؛ هر دو باید جای‌نگهدار `%token` را مطابق الگوی تأییدشده داشته باشند.
- نام دقیق هر دو الگو و کلید API. برای محیط محلی از `scripts/configure-kavenegar.ps1` استفاده کنید؛ در تولید، مقادیر را در مدیریت اسرار قرار دهید.

## درگاه پرداخت

پیش از اتصال باید درگاه و محیط آن مشخص شوند. برای پیاده‌سازی نیاز است:

- نام شرکت ارائه‌دهنده و مستندات رسمی نسخهٔ API که قرار است استفاده شود.
- دسترسی محیط آزمایشی و روش نگهداری امن merchant ID و کلیدهای امضا/احراز هویت.
- قواعد مبلغ و واحد پول (ریال یا تومان)، حداقل/حداکثر تراکنش و نحوهٔ تبدیل مبلغ سفارش.
- مسیرهای بازگشت مرورگر و callback سرور، روش راستی‌آزمایی نتیجه، شناسهٔ یکتای تراکنش و رفتار callback تکراری.
- قواعد لغو، استرداد، مغایرت و تطبیق با گزارش تسویهٔ درگاه.

مدل `PaymentRecord` برای ثبت تلاش پرداخت وجود دارد؛ تا انتخاب درگاه و تأیید قرارداد آن، پرداخت آنلاین و callback واقعی فعال نیستند.

## سامانهٔ قیمت و انبار

برای ساخت adapter به سامانهٔ موجود، این موارد لازم است:

- مستندات API یا OpenAPI، نسخه، نشانی محیط آزمایشی و روش احراز هویت.
- نمونهٔ واقعیِ پاک‌سازی‌شده از پاسخ قیمت، موجودی و خطا؛ اطلاعات مشتری و token را از نمونه حذف کنید.
- نگاشت شناسهٔ کالا/گونهٔ سامانه به SKU یا گونهٔ متناظر در کاتالوگ آریا.
- تعریف واحدها، ارز، مالیات، محل تحویل، زمان مشاهده و مدت اعتبار قیمت و موجودی.
- روش به‌روزرسانی (webhook یا polling)، محدودیت درخواست، صفحه‌بندی، timeout، retry و رفتار زمان قطعی سامانه.

تا زمان دریافت قرارداد، واردسازی CSV و تأیید انسانی قیمت و موجودی مسیر عملیاتی باقی می‌مانند.

## اطلاعات رسمی شرکت و کاتالوگ

- نام ثبتی و نام تجاری، معرفی مورد تأیید، اطلاعات تماس، نشانی و ساعت پاسخ‌گویی.
- سیاست‌های رسمی فروش، مرجوعی، حریم خصوصی، شرایط استفاده، شکایت و صادرات.
- لوگوی نهایی (ترجیحاً SVG یا PNG باکیفیت) و تصاویر محصول با اجازهٔ استفادهٔ وب و اپ.
- فهرست کارخانه، کالا، گونه/SKU، واحد فروش، قیمت و موجودی تأییدشده و محل تحویل.
- نرخ حمل معتبر، محدودهٔ پوشش، مبنای محاسبه و زمان اعتبار هر نرخ.

قیمت، موجودی، نشانی یا سیاست حقوقی نمونه نباید به‌عنوان دادهٔ واقعی شرکت منتشر شود.

## انتشار Android TWA

- دامنهٔ canonical نهایی با HTTPS فعال و قابل دسترس عمومی.
- شناسهٔ یکتای package و نام فروشگاه/بازارچهٔ انتشار.
- اثر انگشت SHA-256 گواهی امضای نسخهٔ انتشار؛ اگر فروشگاه امضای برنامه را مدیریت می‌کند، اثر انگشت گواهی امضای نهایی فروشگاه نیز لازم است.
- آیکون‌های نهایی و متن/تصاویر فهرست انتشار، پیوند پشتیبانی و صفحهٔ حریم خصوصی.

پس از دریافت این موارد، `assetlinks.json` را با دامنه و گواهی نهایی تنظیم و روی HTTPS اعتبارسنجی کنید؛ سپس بستهٔ Android را بسازید و در کانال انتشار منتخب بررسی کنید.

## محیط تولید و عملیات

- میزبان و روش استقرار، دامنه‌ها، TLS/reverse proxy و مدیریت secretها.
- MySQL سازگار با نسخهٔ Django پروژه، حساب برنامه با حداقل دسترسی و مسیر بازیابی اضطراری.
- مقصد پشتیبان جدا از پایگاه اصلی، دورهٔ نگهداری، رمزگذاری، زمان‌بندی و محیط ایزوله برای آزمون restore.
- زمان‌بندی worker قیمت/هشدار، پایش صف خطا و مسیر هشدار خرابی یا پرشدن دیسک.
- کانال و مسئول دریافت هشدارهای عملیاتی و روش دسترسی اضطراری به میزبان.

## ترتیب پیشنهادی تحویل ورودی‌ها

1. اطلاعات شرکت، کاتالوگ و نرخ‌های معتبر برای بازبینی سایت با دادهٔ واقعی.
2. درگاه منتخب و محیط آزمایشی برای تکمیل چرخهٔ پرداخت.
3. قرارداد API قیمت/انبار برای جایگزینی یا تکمیل واردسازی CSV.
4. دامنه، گواهی انتشار و اطلاعات فروشگاه برای ساخت و اعتبارسنجی TWA.
5. مشخصات میزبان تولید و سیاست backup/restore برای انتشار قابل اتکا.
