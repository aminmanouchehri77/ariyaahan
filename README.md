# سایت آهن‌آلات آریا

## تنظیم محیط با فایل .env

در ریشهٔ پروژه، فایل .env محلی از روی .env.example ساخته شده است. فایل .env در Git نادیده گرفته می‌شود. مقدارهای محیطی که از PowerShell یا سرویس استقرار می‌آیند بر مقدارهای فایل اولویت دارند؛ بنابراین اسکریپت محرمانهٔ محلی دیتابیس می‌تواند DB_PASSWORD را بدون ثبت در .env تنظیم کند.

کلید واقعی کاوه‌نگار، درگاه پرداخت، VAPID و مشخصات امضای Android را فقط در مخزن امن سیستم یا تنظیمات محیط استقرار قرار دهید. .env.example فقط نام و شکل این تنظیمات را نشان می‌دهد.

## ورود داده‌های واقعی

قالب‌ها و راهنما در docs/data-import.md قرار دارند. فرمان‌های ورود کاتالوگ، قیمت و موجودی ابتدا اعتبارسنجی می‌کنند و تنها با گزینهٔ صریح --commit در MySQL می‌نویسند. قیمت و موجودی تازه تا تأیید مدیر منتشر نمی‌شوند.

وب‌سایت فارسی با Django، قالب‌های سمت سرور و MySQL. پیاده‌سازی فعلی شامل کاتالوگ، جست‌وجو، دسته‌بندی، صفحهٔ محصول/گونه، تاریخچهٔ قیمت، فرم استعلام، پیام تماس، سبد خرید اولیه، درخواست پیش‌فاکتور و تالارهای عرضه و تقاضا است.

## فناوری و داده

- Python و Django مطابق نسخه‌های `requirements.txt`
- MySQL 8.4، موتور InnoDB و نویسه‌گذاری `utf8mb4`
- قالب‌های Django، HTML، CSS و JavaScript ساده؛ JavaScript برای منوی موبایل و نصب PWA استفاده می‌شود
- PWA پایه با manifest، آیکون نصب، پوستهٔ آفلاین و Service Worker؛ قیمت‌های متغیر در کش آفلاین ذخیره نمی‌شوند
- زیرساخت SEO پایه شامل canonical، robots.txt، sitemap.xml و دادهٔ ساخت‌یافتهٔ سازمان، وب‌سایت و قیمت معتبر محصول
- فرم‌های استعلام قیمت و تماس با اعتبارسنجی شمارهٔ همراه؛ درخواست‌ها از پنل مدیریت دسته‌بندی و پیگیری می‌شوند
- مبلغ به‌شکل `Decimal` ذخیره می‌شود و هر رکورد قیمت زمان، واحد پول، محل تحویل، وضعیت موجودی و تاریخ اعتبار می‌تواند داشته باشد
- سبد خرید ناشناس در نشست مرورگر نگهداری می‌شود؛ مسیرهای `/cart/` و `/checkout/` برای بازبینی اقلام و ثبت درخواست پیش‌فاکتور هستند
- درخواست پیش‌فاکتور و snapshot اقلام/قیمت در MySQL ثبت می‌شود و از پنل `/admin/` قابل پیگیری است؛ snapshotها در پنل فقط‌خواندنی‌اند
- جمع برآورد تنها برای قیمت معتبر، موجود و دارای مبنای واحد سازگار محاسبه می‌شود؛ جمع ارزهای مختلف جداست و مالیات، حمل، موجودی و قیمت نهایی باید توسط کارشناس تأیید شود
- ثبت درخواست به معنی صدور فاکتور مالیاتی، ثبت سفارش قطعی یا پرداخت نیست؛ رسید عمومی با شناسهٔ تصادفی ارائه می‌شود و بدون ذخیره‌سازی عمومی در cache/موتور جست‌وجو نمایش داده می‌شود
- تالارهای `/market/sell/` و `/market/buy/` آگهی‌های فعال را پس از تأیید مدیر نمایش می‌دهند؛ فرم‌ها اطلاعات تماس را خصوصی نگه می‌دارند، نام شرکت فقط با اجازهٔ ثبت‌کننده عمومی می‌شود و آگهی پس از ۳۰ روز از فهرست فعال خارج می‌شود
- آگهی‌های تالار از پنل `/admin/` بررسی و منتشر یا رد می‌شوند؛ پیگیری آگهی از راه فرم تماس به صفحهٔ ثبت‌شده پیوند می‌خورد
- مهاجرت اولیه ده دستهٔ کاتالوگ را ایجاد می‌کند؛ محصولات و قیمت‌ها عمداً ساختگی نیستند و از پنل مدیریت وارد می‌شوند

## آماده‌سازی MySQL محلی

پروژه برای MySQL با `utf8mb4` پیکربندی شده است. روی سیستم توسعه، MySQL Server 9.1 پیدا شده است؛ محیط‌های MySQL سازگار با نسخهٔ Django نصب‌شده را به‌کار ببرید. در PowerShell از ریشهٔ پروژه اسکریپت زیر را اجرا کنید:

```powershell
.\scripts\setup-local-mysql.ps1
```

اسکریپت رمز حساب مدیریتی MySQL را در prompt خود `mysql` می‌گیرد و در فایل پروژه ذخیره نمی‌کند. سپس پایگاه `ariaahan` و کاربر محدود `ariaahan_app` برای اتصال برنامه را می‌سازد و تنظیمات محلی را در `.local-db.ps1` ذخیره می‌کند. Git این فایل را نادیده می‌گیرد؛ آن را commit یا ارسال نکنید. حساب برنامه فقط به پایگاه همین پروژه دسترسی دارد و نیازی نیست Django با کاربر `root` اجرا شود.

درایور `mysqlclient` در `requirements.txt` تعریف شده است. پس از نصب وابستگی‌های پروژه در محیط مجازی، migrationها و اتصال را با اسکریپت انجام دهید:

```powershell
.\scripts\migrate-local.ps1
```

برای اجرای سایت با همین تنظیم محلی:

```powershell
.\scripts\run-local.ps1
```

در صورت نیاز به ساخت مدیر پنل، ابتدا تنظیمات محیط را بارگذاری و سپس فرمان را اجرا کنید:

```powershell
. .\.local-db.ps1
.\venv\Scripts\python.exe manage.py createsuperuser
```

اگر محیط مجازی پروژه با نام `.venv` ساخته شده، مسیر Python را در فرمان آخر به `.venv\Scripts\python.exe` تغییر دهید. پایگاه موقت SQLite دیگر برای اجرای اصلی لازم نیست.

در محیط production همچنین `DJANGO_SECRET_KEY`، `DEBUG=0`، `ALLOWED_HOSTS` و `CSRF_TRUSTED_ORIGINS` را از مدیریت اسرار/محیط استقرار تنظیم کنید. کلید توسعهٔ پیش‌فرض فقط برای اجرای محلی است.

تنظیمات برنامه از `.env` محلی خوانده می‌شوند؛ فایل `.env.example` فقط الگو است و secret واقعی را در Git قرار ندهید. برای ایجاد گروه‌های دسترسی استاندارد پنل، تنظیم DB را بارگذاری و فرمان زیر را اجرا کنید. سپس کاربران staff را از پنل Django به گروه متناسب اضافه کنید:

```powershell
. .\.local-db.ps1
.\venv\Scripts\python.exe manage.py setup_staff_roles
```

## نصب و اجرا

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

پس از اجرای سرور، سایت در `http://127.0.0.1:8000/` و پنل در `http://127.0.0.1:8000/admin/` در دسترس است. دسته‌ها از قبل ساخته می‌شوند؛ ابتدا کارخانه، محصول، گونه و سپس قیمت معتبر با واحد محاسباتی مشخص را ثبت کنید. کاربر می‌تواند کالا را به سبد اضافه و درخواست پیش‌فاکتور ثبت کند، یا آگهی عرضه/تقاضا بفرستد. درخواست‌ها و آگهی‌ها از پنل مدیریت پیگیری می‌شوند.

## انتشار PWA و TWA

برای نصب PWA در محیط واقعی، سایت باید روی دامنهٔ نهایی با HTTPS منتشر شود. فایل‌های manifest و Service Worker آماده‌اند و برای جلوگیری از نمایش قیمت کهنه، صفحه‌های پویا و قیمت‌ها در حالت آفلاین کش نمی‌شوند.

ساخت و انتشار TWA مرحلهٔ بعد از تثبیت دامنه است: لازم است شناسهٔ بستهٔ Android و SHA-256 گواهی امضای انتشار مشخص شود تا فایل معتبر `/.well-known/assetlinks.json` ساخته و روی همان دامنه منتشر شود. تا آن زمان این اتصال عمداً مقدار ساختگی ندارد.

جزئیات پیکربندی و مسیر انتشار در `docs/pwa-twa-operations.md` آمده است. ثبت اشتراک Web Push آماده است، اما ارسال push بیرونی در این نسخه خاموش است. پیش‌فاکتور و سفارش پیاده‌سازی شده‌اند؛ برای پرداخت واقعی ابتدا باید شرکت درگاه پرداخت را انتخاب کند.

فهرست وضعیت قابلیت‌ها و موارد وابسته به اطلاعات شرکت در `docs/implementation-status.md` نگهداری می‌شود.

## ورود و خروج کاربران

ورود مشتری از `/account/login/` با شمارهٔ همراه و کد یک‌بارمصرف انجام می‌شود. در اجرای محلی، اگر کلید و الگوی کاوه‌نگار تنظیم نشده باشند، کد فقط در خروجی کنسول `runserver` نمایش داده می‌شود. برای اتصال کاوه‌نگار، ابتدا باید در پنل آن سرویس وب‌سرویس پیشرفته فعال و یک الگوی تأییدشدهٔ Verify Lookup که جای‌نگهدار `%token` دارد ایجاد شده باشد. سپس از ریشهٔ پروژه اجرا کنید:

```powershell
.\scripts\configure-kavenegar.ps1
```

اسکریپت کلید API را به‌صورت ورودی مخفی می‌گیرد و کلید و نام الگو را در فایل محلی `.local-sms.ps1` با دسترسی محدود به حساب فعلی ویندوز ذخیره می‌کند. این فایل در Git نادیده گرفته می‌شود. پس از آن، سرور را با `.\scripts\run-local.ps1` دوباره اجرا کنید؛ در این حالت OTP از endpoint رسمی Verify Lookup کاوه‌نگار ارسال می‌شود. برای استقرار واقعی، `KAVENEGAR_API_KEY` و `KAVENEGAR_OTP_TEMPLATE` را از مدیریت اسرار محیط استقرار تنظیم کنید و کلید را در مخزن یا کد قرار ندهید.

کد پس از ۵ دقیقه منقضی می‌شود، هر کد حداکثر ۵ بار قابل تلاش است، ارسال مجدد حداقل ۶۰ ثانیه فاصله دارد و برای هر شماره حداکثر ۵ کد در ساعت صادر می‌شود. شماره پس از تأیید به پروفایل مشتری متصل می‌شود و نشست Django ورود را نگه می‌دارد.

صفحهٔ حساب در `/account/` و خروج با یک فرم POST محافظت‌شده در `/account/logout/` انجام می‌شود. خروج، سبد ناشناس همان مرورگر را نگه می‌دارد. هنوز ارسال واقعی پیامک روی این ماشین فعال نشده است؛ برای آن باید کلید API و نام الگوی تأییدشده را با اسکریپت بالا وارد کنید. این ورود مشتری از ورود مدیر Django در `/admin/` جدا است و رمز MySQL هیچ‌گاه رمز ورود مشتری نیست.

## فهرست مقایسه و دیدگاه کالا

مقایسه برای بازدیدکننده در نشست مرورگر نگه داشته می‌شود. پس از ورود مشتری، فهرست به حساب منتقل و در MySQL ذخیره می‌شود. هر مشتری برای هر کالا یک دیدگاه امتیازی می‌تواند ثبت کند؛ دیدگاه‌ها، پرسش‌های کالا و نظرهای مقاله تا تأیید گروه محتوایی/پشتیبانی یا مدیر منتشر نمی‌شوند. مقاله‌های مجله از پنل مدیریت می‌توانند به کالاهای مرتبط وصل شوند. صفحهٔ کالا دکمهٔ اشتراک‌گذاری و چاپ هم دارد.

هشدار قیمت می‌تواند بر مبلغ هدف یا تغییر درصدی از قیمت معتبر هنگام ثبت تکیه کند. هشدار درصدی پس از اعلان متوقف می‌شود؛ کاربر می‌تواند هشدار را ویرایش یا دوباره فعال کند. صفحهٔ تاریخچه بازه‌های ۷، ۳۰، ۹۰ و ۳۶۵ روز و همهٔ سوابق را دارد.

## پشتیبان‌گیری محلی از MySQL

پشتیبان محلی شامل اطلاعات مشتری و سفارش است. فایل‌ها در پوشهٔ نادیده‌گرفته‌شدهٔ `backups/` با دسترسی محدود به حساب فعلی ویندوز ساخته می‌شوند. ابزارهای MySQL Client و فایل محلی `.local-db.ps1` باید آماده باشند:

```powershell
.\scripts\backup-local-mysql.ps1
```

برای بازگردانی، نام فایل را از پوشهٔ `backups/` بدهید. اسکریپت دیتابیس تنظیم‌شده را جایگزین می‌کند و پیش از اجرا نام دیتابیس و واژهٔ `RESTORE` را جداگانه می‌پرسد:

```powershell
.\scripts\restore-local-mysql.ps1 -BackupFile .\backups\ariaahan-YYYYMMDD-HHMMSS.sql
```

این اسکریپت‌ها فقط عملیات محلی را پوشش می‌دهند. برای تولید، زمان‌بندی پشتیبان، نگهداری نسخهٔ رمزگذاری‌شده در محل جداگانه، هشدار خرابی و آزمون دوره‌ای بازگردانی روی پایگاه جداگانه باید در زیرساخت استقرار تنظیم شود.
